# Агентам: как работать с хранилищем

Хранилище — бэклог и память команды: статусы, решения владельца, история версий, журнал, ID файлов. Результаты работы (тексты, сценарии, код, рендеры) живут в репозитории проекта, здесь только ссылки на них.

Файлы на диске доступны всегда, поэтому по умолчанию читай их через Read и Grep. MCP-сервер Obsidian, если подключён, отвечает только пока открыт Obsidian.

## Читать экономно

1. Основная сессия: доска статуса подгружается хуком в начале сессии. Если её нет в контексте — прочитай `Статус.md`, больше ничего на старте.
2. Задача по проекту: хаб `Проекты/<Проект>/<Проект>.md`, разделы «Сейчас» и «Решения». Заметку задачи открывай, только если работаешь над ней. Каждый хаб и задача начинаются со свёрнутого блока «Кратко»: прочитай эти 2–3 строки и дальше не читай, если заметка не про то.
3. Найти факт: Grep по хранилищу в режиме `files_with_matches`, потом Read нужных строк. Через MCP: `search_simple`, затем `vault_read` с `targetType: heading`; путь раздела начинается с заголовка H1, например `["Тизер","Сейчас"]`.
4. ID внешних файлов, команды рендера, инструменты: папка `Справка/`.
5. `Система/` — автокопии агентов, скиллов, правил, памяти и сессий для владельца. Агентам они не нужны, оригиналы под рукой. Исключение — история сессий, когда владелец спрашивает «что мы делали с…».
6. Правила проекта читай в оригинале (`CLAUDE.md` в репозитории).

## Писать

- **Субагент:** результат сохраняет в репозиторий, как обычно. В хранилище — только одна строка в журнал месяца `Журнал/YYYY-MM.md`: `- ДД.ММ · <проект> · <агент> · что сделано → путь`. «Статус» и хабы не трогает.
- **Основная сессия** после каждой завершённой задачи или контрольной точки:
  - правит строку в `Статус.md`;
  - в заметке задачи обновляет «Сейчас» и «Версии», во frontmatter `status`, `updated`, `next`;
  - дописывает решение владельца в «Решения»: дата, что решили, почему. Отклонённое тоже, чтобы не предлагать повторно;
  - переписывает блок «Кратко», если состояние задачи изменилось.
- `Система/Доска.md` (канбан) собирается из `Статус.md`, `Система/Проверка.md` — список застрявших задач, битых ссылок, пустых полей и активных задач, которых нет в «Статусе». Оба пересобираются при каждой синхронизации. Число замечаний видно в начале сессии; разбирать их в заметках примерно раз в неделю.
- Новая задача, ролик или продукт: заметка по `Шаблоны/Задача.md` в папке проекта и строка в «Статус».
- В `Система/` не писать: синхронизация затрёт.
- Секреты (токены, ключи, пароли) в хранилище не писать. Только имя переменной окружения.
- Коротко: списки, пути в `коде`, ссылки на заметки. Тексты постов, сценарии и код не копировать, давать путь к файлу.

## Свойства заметок

```yaml
type: проект | задача
project: Студия            # имя хаба
status: идея | в работе | ждёт владельца | пауза | готово | отклонено
updated: 2026-11-01
next: что сделать дальше, одна строка
```

Поиск по статусу: Grep `status: ждёт владельца` по `Проекты/` или MCP `search_query` с `{"==":[{"var":"frontmatter.status"},"ждёт владельца"]}`.
