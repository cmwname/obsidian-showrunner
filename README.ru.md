---

У вас основная сессия Claude и несколько агентов: ресёрчер, автор, дизайнер, монтажёр. Через неделю уже непонятно, что в работе, что ждёт вас, почему выкинули четвёртую версию и что вообще написано в промпте дизайнера. Claude тоже не знает: каждая новая сессия начинается с чтения статус-файла на 15 КБ или, хуже, с предложения того, что вы отклонили во вторник.

Showrunner превращает хранилище Obsidian в бэклог и память команды и сам держит его в актуальном состоянии.

## Что получаете

- **Доску статуса, которую Claude подгружает сам.** `Статус.md`: ждёт вас, в работе, прервано, дальше. Хук подкладывает её в начале сессии, и Claude знает положение дел раньше, чем вы что-то напишете.
- **Канбан, который ведёт себя сам.** Из доски статуса при каждой синхронизации собирается канбан (`Система/Доска.md`). Один источник, два вида, ни одной лишней записи.
- **Сводку наверху каждой заметки.** Свёрнутый блок «Кратко» на 2–3 строки: что это и где сейчас. Агенты читают его и пропускают ненужные заметки, вы сначала видите содержание.
- **Проверку хранилища.** `Система/Проверка.md`: застрявшие задачи, битые ссылки, пустые поля, задачи, выпавшие из «Статуса». Число замечаний Claude видит в начале сессии и раз в неделю наводит порядок.
- **Решения, включая отклонённые.** У каждой задачи разделы «Сейчас», «Версии», «Решения». Запись «v04 отклонён: слишком похоже на референс» остаётся, и никто не предложит это снова.
- **Правила записи для нескольких агентов.** Статус и решения ведёт основная сессия. Агенты дописывают одну строку в журнал месяца. Никаких конфликтов и пяти агентов, переписывающих одну заметку.
- **Живое зеркало настройки.** Агенты с промптами, скиллы, все `CLAUDE.md`, авто-память Claude — всё видно в Obsidian и пересобирается после каждого ответа.
- **Историю сессий, которую можно читать.** Каждая сессия — заметка с вашими запросами по порядку, проектами и вызванными агентами. Прошлые месяцы складываются в папку на месяц. Токены и ключи замаскированы.
- **Экономию токенов.** Агенты читают доску, потом ищут Grep'ом и открывают только нужный раздел. Хранилище целиком в контекст не попадает.
- **Работу без открытого Obsidian.** Хранилище — обычные файлы. Если подключён MCP-сервер Obsidian (Local REST API), агенты дополнительно читают отдельные разделы и ищут по свойствам заметок.

## Установка

```text
/plugin marketplace add cmwname/obsidian-showrunner
/plugin install showrunner@showrunner
/showrunner:setup
```

Мастер спросит, какое хранилище использовать (он читает список хранилищ Obsidian), какие папки — отдельные проекты, и предложит перенести существующий `STATUS.md` или `backlog.md`. Для русского выберите `"lang": "ru"`: заметки и подписи будут на русском.

**Нужно:** Claude Code, Python 3.8+, bash (на Windows он идёт с Git for Windows, который Claude Code и так требует). Obsidian с плагином Local REST API для MCP — по желанию.

[`examples/demo-vault`](examples/demo-vault) — хранилище вымышленного канала про велосипеды с тремя агентами. Откройте его в Obsidian и начните с `00 Home.md`.

## Конфиденциальность

- В хранилище лежат ваши запросы. Держите его закрытым, не выкладывайте в публичный репозиторий.
- Маскировка работает по шаблонам: токены Telegram и AWS, ключи вида `sk-`/`ghp_`, JWT, `password=…` и любые строки длиннее 40 символов вне ссылок. Частые случаи ловит, но не все. После первой синхронизации мастер проверяет результат.
- Пути в заметках показываются как `~/…` и `./…`, имя пользователя в хранилище не попадает.
- Никаких сетевых запросов и телеметрии.

Подробности, сравнение с похожими проектами и настройки — в [README на английском](README.md).
